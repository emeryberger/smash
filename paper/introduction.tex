\section{Introduction}
\label{sec:intro}

A significant fraction of allocated memory is cold at any given
moment.  Studies of production workloads report that
20--50\% of resident pages have not been accessed in the last
60~seconds~\cite{maas2020adaptive,amaro2023memory}.
Operating systems already exploit this observation: Linux
zswap~\cite{jennings2013zswap} compresses pages at swap-out time,
macOS uses WKdm~\cite{wilson1999case,apple2013compressed} for
inactive pages, and Meta's TMO~\cite{weiner2022tmo} offloads cold
pages to compressed swap at datacenter scale.

These OS mechanisms are \emph{reactive}. They compress only when
the system is under memory pressure. They are also \emph{structure-blind}:
each page is treated as an opaque 4\,KiB (or 16\,KiB) byte array.
Unfortunately, conventional allocators are likely to produce pages that are
hostile to compression.  A typical page intermixes objects from
unrelated call sites, which could group wildly different objects (e.g., a JSON record next to a hash-table node next to a connection buffer). Conventional allocators also use object headers to manage freelist pointers; the allocator
rewrites these on every \tcode{malloc} and \tcode{free}. When objects are freed, their
slate contents remain intact. The freelist writes thus keep pages ``warm'' in the
OS's access-tracking sense even when application data is cold, and
their heterogeneous content compresses poorly, and compression effort is wasted on freed objects.
Our compress-only experiment (\S\ref{sec:eval:pipeline}) confirms
this: layering a compression pipeline atop the unmodified system
allocator \emph{increases} RSS by 6--24\% due to metadata overhead
that is not offset by compression savings, because glibc's pages
contain too much incompressible noise.

\sys is a drop-in replacement memory allocator designed to make
transparent heap compression effective.  Its key insight is that
\emph{allocation and compression can cooperate to improve
compressibility}. \sys's allocator produces pages that are maximally
compressible, and its compressor exploits structural knowledge of the
heap to compress them efficiently.  \sys incorporates allocator-level
techniques designed to improve page compressibility:

First, \sys \textbf{segregates data from heap metadata}. \sys employs
  out-of-band bitmaps rather than in-band object headers.
  Unlike conventional allocators where data and heap metadata are intermingled,
  leading to every
  \tcode{malloc}/\tcode{free} touching adjacent data pages,
  \sys{} avoids disrupting the reference behavior of data
  (\S\ref{sec:design:arch}).

  % \item
  Second, \sys \textbf{segregates objects by their size and their call site}.
  Each \tcode{malloc}
  hashes its return address to route allocation to one of four
  arenas, so same-sized objects from the same call site share pages. This grouping
  yields structurally homogeneous page content (similar field
  layouts, similar byte patterns) that can further improve compression
  (\S\ref{sec:design:arenas}).
  % \item
% \end{enumerate}
  Finally, \sys \textbf{lazily zeroes freed objects} at compression time (using non-temporal stores to avoid cache pollution), replacing stale data with runs of zeroes. This approach keeps the \tcode{free} path fast while dramatically improving compression ratios
  (\S\ref{sec:design:zero}).

  % \noindent
  
On top of its compression-friendly allocator, \sys incorporates a background
compressor that applies \textbf{JIT compression}: like a JIT compiler
that profiles methods to decide which to optimize and at what level,
\sys tracks per-size-class compression statistics and employs a
return-on-investment (ROI) model to decide \emph{whether} to compress
each cold page and \emph{which} algorithm to use: zstd-1 for
recently cold pages where fast compression minimizes risk, and
zstd-9 for long-idle pages where the better ratio justifies the
higher CPU cost.  Accessed pages are decompressed and reset,
analogous to deoptimization (\S\ref{sec:design:adaptive}).

We evaluate \sys on four real-world, memory intensive applications.  \sys reduces serve-phase
RSS by \rssRedMin--\rssRedMax\% with negligible throughput impact:
memcached \ablMemcachedBaselineServeRss$\to$\ablMemcachedDefaultServeRss\,MiB
(\ablMemcachedDefaultRssRedInt\%),
RocksDB \ablRocksdbBaselineServeRss$\to$\ablRocksdbDefaultServeRss\,MiB
(\ablRocksdbDefaultRssRedInt\%),
SQLite \ablSqliteBaselineServeRss$\to$\ablSqliteDefaultServeRss\,MiB
(\ablSqliteDefaultRssRedInt\%),
Redis \ablRedisBaselineServeRss$\to$\ablRedisDefaultServeRss\,MiB
(\ablRedisDefaultRssRedInt\%).
An ablation study quantifies each technique's contribution;
no allocator tested (including
Mesh~\cite{powers2019mesh}) reduces RSS below its fill level
without compression.

In some cases, modest application changes can further improve
\sys's effectiveness.  By deferring Redis's background maintenance
tasks during idle periods and caching two object-metadata fields
to avoid dereferencing value data on \tcode{DEL}
(7~files, 105~lines changed), we reduce Redis's baseline RSS
from \ablRedisBaselineServeRss\ to
\ablRedisPatchedBaselineServeRss\,MiB
(\redisPatchBaselineRedPct\% \emph{without any compression}),
and make the remaining cold data consistently compressible
(\S\ref{sec:eval:apps}).
