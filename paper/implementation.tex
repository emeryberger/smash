\section{Implementation}
\label{sec:impl}

\sys is implemented as a single shared library (5,200 lines of C++
across headers and one compilation unit) for macOS and Linux. It uses the alloc8
framework~\cite{berger2025alloc8} to replace all allocation operations
(e.g., \texttt{malloc}/\texttt{free}) via library interposition
(\tcode{DYLD\_\allowbreak INSERT\_\allowbreak LIBRARIES} on macOS,
\tcode{LD\_\allowbreak PRELOAD} on Linux).
%On macOS, the
%\texttt{\_\_interpose} section redirects cross-dylib GOT entries;
%on Linux, strong symbol definitions in the preloaded library
%override glibc's weak defaults.
% The Linux version uses an
% unversioned linker script (no \texttt{GLIBC\_2.x} tags) so that a
% single binary works across architectures---x86\_64 expects version
% \texttt{2.2.5} while aarch64 expects \texttt{2.17}.

\subsection{Parallel Compressor}
\label{sec:impl:parallel}

The compressor uses a coordinator-worker model.  The coordinator
thread wakes every second, partitions the committed page range
across the currently active workers, and dispatches all three
phases.  The active worker count is set adaptively each tick using
Little's Law (\S\ref{sec:impl:little}); workers are pre-allocated
up to \tcode{kMaxCompressorWorkers} (default~8) with helper threads
lazily created on first scale-up and parked when
idle.

\paragraph{Chunk bitmap}  Rather than scanning all committed
pages linearly, the compressor maintains a bitmap with one bit per
64-page chunk.  A set bit indicates at least one non-EMPTY page.
The bitmap is rebuilt each tick.  Iteration uses
count-trailing-zeros to jump to set bits, reducing scan time from
$O(\text{committed})$ to $O(\text{active pages})$.

\paragraph{Per-worker state}  Each worker has its own LZ4 state
buffer, zstd compression context (\tcode{ZSTD\_\allowbreak CCtx}), page-sized
scratch buffer, and compression output buffer.  Workers share only the
dictionary lookup table (read-only during compression) and the
sharded compressed data~store.

\paragraph{Sharded CompressStore}  Compressed page data is stored
in a pool with 8~independent shards, each with its own spinlock
and bump allocator.  Allocations are exact-size with 16-byte
alignment rather than power-of-two rounding, so a 500-byte
compressed blob consumes exactly 512~bytes (rounded to alignment)
rather than 1\,KiB.  Pages are assigned to shards by index
modulo~8.  Each shard's backing regions (16\,MiB each) track live
bytes; when a region's live bytes drop to zero, its data pages are
decommitted (\tcode{MADV\_\allowbreak FREE\_\allowbreak REUSABLE} on
macOS, \tcode{MADV\_\allowbreak DONTNEED} on Linux), releasing
physical memory while preserving the virtual mapping.  With up to
eight workers and eight shards, lock contention is near~zero.

\paragraph{Adaptive worker scaling via Little's Law}
\label{sec:impl:little}
The right number of workers depends on the workload.  An idle
program needs one; a bulk-allocation phase may need several.
With too few workers, the compression queue grows faster than it
drains and cold pages stay uncompressed.  With too many, idle
helpers consume CPU and scheduler bandwidth for no gain.
\sys sizes the worker pool each tick by treating the compressor
as a simple queueing system and applying Little's Law.

Let $\lambda$ be the rate at which pages become eligible for
compression (cold-count reaches the threshold and the ROI model
accepts) and $\mu$ be the rate at which a single worker compresses
pages.  For a stable queue with expected length $L$ and expected
wait $W$, $L = \lambda W$; equivalently, to keep the queue drained
($L \to 0$), the aggregate service rate across $N$ workers must
match arrival, $N \mu \geq \lambda$.  \sys uses the tight~bound,
\[
  N_{\mathit{needed}} \;=\; \left\lceil \lambda / \mu \right\rceil,
\]
clamped to $[1, \tcode{kMaxCompressorWorkers}]$.  Both quantities
are measured in pages per tick; units cancel, so
$N_{\mathit{needed}}$ depends only on the arrival-to-service ratio
and not on the tick length.  Each worker maintains two atomic
counters per tick (pages eligible, pages compressed), which the
coordinator sums after dispatch.  Per-worker throughput $\mu$ is
the tick's $\mathit{total\_compressed} / N$.  Both $\lambda$ and
$\mu$ are smoothed with an exponential moving average computed in
fixed point to avoid floating-point in the compressor:
$\mathrm{ema} \mathrel{+}= (\mathrm{sample} - \mathrm{ema})/4$.
The resulting four-tick response is fast enough to track phase
changes (e.g., load versus serve) and slow enough to avoid
oscillation on a single noisy tick.  \sys only updates $\mu$ on
ticks with work, so that idle periods do not decay it to zero and
cause spurious scale-up when work resumes.  Pre-allocating the
worker state array and lazily \texttt{pthread\_create}-ing helpers
avoids allocator reentrancy during a scale-up inside the
compression~path.

\Function{CompressorTick}{}
  \State rebuild chunk bitmap
  \State partition page range across workers
  \State $\triangleright$ \textit{Phase 1: update cold counts}
  \ForAll{active pages $p$ (via chunk bitmap)}
    \If{$p$ was accessed since last tick}
      \State $\mathit{cold}[p] \gets 0$
    \Else
      \State $\mathit{cold}[p] \mathrel{+}= 1$
    \EndIf
  \EndFor
  \State $\triangleright$ \textit{Phase 2: compress cold pages}
  \ForAll{pages $p$ with $\mathit{cold}[p] \geq \textsc{ColdFloor}$}
    \State \Call{CompressPage}{$p$}
  \EndFor
  \State $\triangleright$ \textit{Phase 3: set up access monitoring}
  \ForAll{remaining \textsc{active} pages $p$}
    \State \Call{mprotect}{$p$, \textsc{prot\_read}}
    \State $\mathit{state}[p] \gets$ \textsc{active\_monitoring}
  \EndFor
\EndFunction
\Statex
\Function{CompressPage}{$p$}
  \State \Call{Lock}{$p$};\; $\mathit{state}[p] \gets$ \textsc{compressing}
  \State $R \gets \Call{AvgRatio}{\mathit{sc}}$
  \Comment{from sliding window}
  \If{$\Call{ROI}{\mathit{cold}[p], R} < \textsc{Threshold}$}
    \State $\mathit{state}[p] \gets$ \textsc{active};\; \Call{Unlock}{$p$};\; \Return
  \EndIf
  \State \Call{mprotect}{$p$, \textsc{prot\_read}}
  \Comment{snapshot}
  \State $\mathit{buf} \gets$ copy page into worker scratch buffer
  \State zero freed slots in $\mathit{buf}$ (non-temporal stores)
  \State \Call{Decommit}{$p$}
  \Comment{before \textsc{prot\_none}}
  \State \Call{mprotect}{$p$, \textsc{prot\_none}}
  \State $\mathit{algo} \gets \Call{BestAlgo}{\mathit{cold}[p], R}$
  \Comment{highest-ROI algorithm}
  \State $\mathit{blob} \gets \Call{Compress}{\mathit{buf}, \mathit{algo}}$
  \If{$|\mathit{blob}| > \textsc{MinRatio} \times \textsc{PageSize}$}
    \If{$\mathit{algo} =$ fast tier}
      \Comment{fall back to deep}
      \State $\mathit{blob} \gets \Call{Compress}{\mathit{buf},\;\text{zstd-9}}$
    \EndIf
    \If{$|\mathit{blob}| > \textsc{MinRatio} \times \textsc{PageSize}$}
      \State restore $p$ from $\mathit{buf}$;\; \Call{Unlock}{$p$};\; \Return
    \EndIf
  \EndIf
  \State store $\mathit{blob}$ in sharded \textsc{CompressStore}
  \State $\mathit{state}[p] \gets$ \textsc{compressed};\; \Call{Unlock}{$p$}
\EndFunction

\paragraph{Physical page reclamation}
Marking a page \texttt{PROT\_NONE} prevents access but does not
release its physical backing.  \sys releases the backing with
\texttt{madvise}.  On Linux it calls
\texttt{madvise(MADV\_\allowbreak DONTNEED)}.
On macOS it calls
\texttt{madvise(MADV\_\allowbreak FREE\_\allowbreak REUSABLE)},
the hint that actually returns frames to the kernel (this is what
jemalloc and WebKit use).  The macOS hint fails with
\texttt{EPERM} on \texttt{PROT\_NONE} pages, so \sys issues the
\texttt{madvise} call while the page is still \texttt{PROT\_READ}
and then transitions it to \texttt{PROT\_NONE}
(Figure~\ref{fig:algo:compress}).

\subsection{Fault Handler}
\label{sec:impl:fault}

\sys installs a signal handler for both SIGSEGV and SIGBUS.  The
handler receives the faulting address, looks up the page index in the
VM region, acquires the per-page lock, and takes action based on page
state.  For a \textsc{compressed} page, the handler recommits the
physical page, decompresses the stored data, releases the compressed
blob, and transitions to \textsc{active}.  For an
\textsc{active\_monitoring} page (a write to a read-only monitored
page), the handler restores read-write permission and transitions to
\textsc{active}.  The handler never observes the \textsc{compressing}
state: the compressor holds the per-page lock throughout compression,
so the handler blocks until the page reaches \textsc{compressed} or
returns to \textsc{active} (\S\ref{sec:impl:formal}).  Finally, a fault on an \textsc{active} page
indicates a race where Phase~3's batched \texttt{mprotect} overwrote a
per-page permission restoration from a concurrent fault handler; the
handler restores write~permission.

\begin{figure}[t]
\begin{algorithmic}[1]
\Function{HandleFault}{$\mathit{addr}$}
  \State $p \gets \Call{PageIndex}{\mathit{addr}}$
  \State \Call{Lock}{$p$}
  \If{$\mathit{state}[p] =$ \textsc{compressed}}
      \State $\mathit{slot} \gets \Call{AcquireFaultSlot}{}$
      $\triangleright$ \textit{CAS}
      \State \Call{Decompress}{$\mathit{slot.dctx}$, $\mathit{blob}$, $\mathit{slot.buf}$}
      \State \Call{Recommit}{$p$};\; copy $\mathit{slot.buf} \to p$
      \State release compressed blob;\; \Call{ReleaseFaultSlot}{$\mathit{slot}$}
      \State $\mathit{state}[p] \gets$ \textsc{active};\; $\mathit{cold}[p] \gets 0$
      \State \Call{PrefetchAdjacent}{$p$}
  \ElsIf{$\mathit{state}[p] =$ \textsc{active\_monitoring}}
      \State \Call{mprotect}{$p$, \textsc{prot\_read|write}}
      \State $\mathit{state}[p] \gets$ \textsc{active}
  \EndIf
  \State \Call{Unlock}{$p$}
\EndFunction
\end{algorithmic}

\paragraph{Per-slot decompression contexts}
The signal handler must not call \tcode{malloc}.  All decompression
state is pre-allocated from a bootstrap allocator.  \sys maintains
128~fault slots, each with a pre-allocated page buffer and an
independent zstd decompression context.  A faulting thread atomically
acquires a slot via compare-and-swap, decompresses into the slot's
buffer, copies the result to the faulting page, and releases the slot.
If all slots are in use, the handler spin-waits with
architecture-specific pause instructions (\tcode{pause} on x86, \tcode{yield} on ARM) until
a slot becomes available.  Since the thread is already blocked on the
page fault, it cannot proceed without decompressing.  Prefetch, which is
an optional optimization, instead skips any page for which no slot is
available.  This design supports high-concurrency workloads (e.g.,
multi-threaded servers) without data~races on zstd internal state.

\paragraph{Concurrent faults on the same page}
When multiple threads fault on the same compressed page simultaneously,
the per-page lock serializes access: only the first thread (the ``winner'')
decompresses the page; subsequent threads acquire the lock after the
winner releases it, observe that the page is now \textsc{active}, and
return immediately.  The lock uses acquire-release memory ordering,
ensuring that the winner's \texttt{memcpy} of decompressed data
happens-before any loser's read of that data.

\paragraph{Prefetch}
After decompressing a faulted page, the handler speculatively
decompresses up to \texttt{kPrefetchWindow} = 2 pages in each
direction, provided they belong to the same span and are in the
COMPRESSED state.  Prefetch uses non-blocking \texttt{tryLock} to
avoid deadlock with concurrent fault handlers.  Prefetch reduces
cold-access latency in sequential access patterns; memcached's cold
key re-access throughput improves by 54\% with prefetch.

\paragraph{Bootstrap allocator}
All \sys internal metadata (page state arrays, compressed data store,
decompression contexts, worker buffers) is allocated from a bump
allocator (\texttt{BootstrapAlloc}) backed by \texttt{mmap}.  The
bootstrap allocator never calls \texttt{malloc} and never frees memory.
This design is critical for the signal handler path, which must
be async-signal-safe.

\paragraph{Thread initialization}
On macOS, the Objective-C runtime creates threads during dyld
initialization, so the compressor is started after the second
\texttt{threadInit} call to avoid interfering with early
bootstrapping.  On Linux, no such threads are created; instead,
\sys registers a GCC constructor function (priority~201) that calls
\texttt{threadInit} for the main thread and starts the compressor
immediately.  The priority ensures that the allocator itself
(priority~200) is initialized~first.

\subsection{Syscall Compatibility}
\label{sec:impl:syscall}

Kernel system calls access userspace buffers directly through
\texttt{copyin}/\texttt{copyout}.  If \sys has marked a buffer page
as \texttt{PROT\_READ} (monitoring) or \texttt{PROT\_NONE}
(compressed), the kernel returns EFAULT rather than triggering a
signal.  This affects any syscall that accesses userspace memory:
\texttt{read}, \texttt{write}, \texttt{recv}, \texttt{send},
\texttt{kevent}, and~others.

\sys interposes on $\sim20$ system calls and C library I/O functions.
Before each call, the wrapper walks the buffer's pages, touching any
page managed by \sys to trigger decompression via the fault handler,
then pins the pages to prevent the compressor from re-protecting them
during the syscall.  After the syscall returns, pages are unpinned.

Page pins are implemented as per-page atomic counters
(\texttt{g\_page\_pins}).  The compressor skips pages with a nonzero
pin count in both Phase~2 (compression) and Phase~3
(monitoring).

\paragraph{Buffered I/O (macOS)}  On macOS, DYLD interposition only
intercepts cross-dylib calls.  When the application calls
\texttt{fread}, the C library internally calls \texttt{read} within
the same dylib (libSystem); \sys's \texttt{read} interposition does
not see this internal call.  \sys addresses this by also interposing
\texttt{fread}, \texttt{fgets}, \texttt{fgetc}, \texttt{fwrite}, and
\texttt{fflush}, warming both the user buffer and the
\texttt{FILE} struct's internal buffer.  Additionally, the
compressor permanently pins the internal buffers of \texttt{stdin},
\texttt{stdout}, and \texttt{stderr} on its first tick, covering
the intra-libSystem blind spot for standard streams.

\paragraph{Linux syscall wrappers}
On Linux, \texttt{LD\_PRELOAD} overrides \emph{all} calls to an
interposed function, including calls within glibc itself.
Consequently, \texttt{fread}'s internal call to \texttt{read} is
intercepted, and separate buffered-I/O wrappers are unnecessary.
However, Linux introduces a different challenge: glibc invokes
\texttt{read}, \texttt{write}, and \texttt{poll} during early
process startup, before any constructors run.  On macOS, the
interpose mechanism is passive (the dynamic linker fills in the
original function pointer before any code executes), but on Linux
the wrappers must resolve the original function via \texttt{dlsym},
which is unavailable during early~init.

\sys solves this with \emph{lazy resolution}: each wrapper stores a
static function pointer initialized to \texttt{nullptr} and calls
\texttt{dlsym} on first invocation.  If the pointer is still null
(because \texttt{dlsym} is not yet available, or because
\texttt{dlsym} itself triggered the wrapper recursively), the wrapper
falls through to a raw \texttt{syscall()} path.  This is safe because
no pages are compressed during early initialization.  An atomic
recursion guard prevents infinite loops when \texttt{dlsym}'s internal
heap allocation triggers the wrapped \texttt{read} or
\texttt{write}~calls.

Linux event-driven servers (memcached, Redis) use \texttt{epoll}
rather than macOS's \texttt{kevent}.  \sys wraps both
\texttt{epoll\_wait} and \texttt{epoll\_pwait}, warming and
pinning the output event array.  These wrappers bypass
\texttt{dlsym} entirely and always invoke the kernel directly via
raw \texttt{syscall()}, avoiding self-resolution issues.
Similarly, the \texttt{poll} wrapper converts its millisecond
timeout to a \texttt{timespec} for the \texttt{ppoll} syscall,
since aarch64 Linux does not provide a \texttt{poll}
syscall~number.

All syscall wrappers require explicit default visibility
annotations, since the library is compiled with hidden visibility
by default; without this, the dynamic linker cannot see the
wrapper symbols for~interposition.

\subsection{Coexisting with a Host Allocator}
\label{sec:impl:largeonly}

Some language runtimes ship their own small-object allocator.
CPython~3.13, for example, builds mimalloc into the interpreter and
routes Python-level allocations through it unless
\texttt{PYTHONMALLOC=malloc} is set.  Under full \sys interposition
the interpreter's small-object path is redirected to \sys regardless
of what the runtime would prefer, which is both slower and
unhelpful (the small objects are hot and rarely compress).  \sys
therefore offers a \emph{large-only} mode, enabled with
\texttt{SMASH\_\allowbreak LARGE\_\allowbreak ONLY=1}: allocations
up to \texttt{kMaxSmallSize} (16\,KiB, matching the boundary between
slab and large-allocation classes) pass through to the host
allocator, and only requests above that threshold go through \sys's
slab and compressible VM region.  \texttt{free} and
\texttt{malloc\_size}/\texttt{malloc\_\allowbreak usable\_\allowbreak size}
consult the page map first and delegate to the host allocator when
the pointer is not \sys-managed.

\paragraph{Locating the host allocator on macOS}
Passthrough requires calling the \emph{unwrapped} system malloc,
but DYLD interposition is truly global on macOS: once \sys's
library is loaded, every call site for \texttt{malloc}, including
\texttt{dlsym(RTLD\_\allowbreak NEXT, \allowbreak"malloc")} and
even
\texttt{dlopen("libsystem\_malloc.dylib")+\allowbreak dlsym}, is
rewritten to point at \sys's wrapper.  To recover the original
function pointer, \sys scans the Mach-O \texttt{\_\_interpose}
section at runtime.  Each interpose entry is a
\texttt{\{replacement,\allowbreak\ original\}} pair; \sys walks the
section, matches its own wrapper address as the replacement, and
reads the paired original.  On ARM64e (Apple Silicon) the section
specified in source as \texttt{\_\_DATA,\_\_interpose} is
relocated by the linker to \texttt{\_\_AUTH\_CONST,\_\_interpose}
to accommodate authenticated pointer signing, so \sys scans both
segments.  Linux has no equivalent issue: symbols resolved with
\texttt{dlsym(RTLD\_\allowbreak NEXT,~...)} return the next
definition in the search order, bypassing
\texttt{LD\_\allowbreak PRELOAD}.

\subsection{Formal Verification}
\label{sec:impl:formal}

The page state machine coordinates a background compressor thread
and concurrent application threads through shared mutable state
(page states, protection bits, per-page locks) with no global lock.
Reasoning about the resulting interleavings informally is
error-prone: subtle races arise from the gap between multi-step
operations (lock, set state, mprotect, compress, unlock) and the
single-step transitions shown in the state diagram.

We model the core protocol in PlusCal~\cite{lamport:pluscal}, a
high-level algorithm language that compiles to
TLA\textsuperscript{+}~\cite{lamport:tla}.  The model captures two
application threads that non-deterministically access pages (faulting
when protection is insufficient) and a three-phase compressor that
scans, compresses, and monitors pages.  Per-page locks, protection
bits, cold counts, and blob/physical-page ownership are all explicit
state variables.  The TLC model checker exhaustively explores
all interleavings.

\paragraph{Safety invariants}  Two invariants are checked in every
reachable state.  \emph{BlobIntegrity} says that a page is in
\textsc{compressed} state if and only if a compressed blob exists
and the physical page has been decommitted.
\emph{ProtectionConsistency} says that page protection matches
page state (e.g., \textsc{compressed} implies
\texttt{PROT\_NONE}).

\paragraph{Liveness properties}  Under strong fairness, TLC verifies
two liveness properties: (1)~every faulted thread eventually resumes,
and (2)~every sufficiently cold monitored page is eventually
compressed or re-accessed.

\paragraph{Bugs found and confirmed}  Model checking revealed that
Phase~3's original state update was unsafe.  The original code was
a plain store of \textsc{active\_monitoring}: between checking a
page's state and writing the new state, a concurrent fault handler
could transition the page to \textsc{active}, and the store would
silently overwrite it.  The fix, now in the implementation, is a compare-and-swap
that abandons the transition if the page is no longer \textsc{active}.
The model also proved that the fault handler can never observe a page
in \textsc{compressing} state, because the compressor holds the
per-page lock for the entire duration of compression; the fault
handler blocks on the lock and sees only \textsc{compressed} or
\textsc{active}.  We confirmed both findings with runtime assertions
(\texttt{\_\_builtin\_trap}) across the full benchmark suite (576~runs,
zero crashes).

\paragraph{Verification scale}  With 3~pages, 2~threads, and a
cold threshold of~2, TLC explores 4.5~million distinct states
and verifies all safety invariants and liveness properties in
42~minutes.  The PlusCal source and TLC configuration are included
in the repository (\texttt{paper/SmashCore.tla}).
