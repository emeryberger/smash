\section{Implementation}
\label{sec:impl}

\sys is implemented as a single shared library (5,200 lines of
C++ across headers and one compilation unit) that interposes on
\texttt{malloc}/\texttt{free} via dyld library interposition on
macOS and \texttt{LD\_PRELOAD} on Linux.  On macOS, the
\texttt{\_\_interpose} section redirects cross-dylib GOT entries;
on Linux, strong symbol definitions in the preloaded library
override glibc's weak defaults.

\subsection{Parallel Compressor}
\label{sec:impl:parallel}

The compressor uses a coordinator-worker model with
two parallel workers (configurable).  The coordinator thread wakes
every second, partitions the committed page range across workers,
and dispatches all three phases.

\paragraph{Chunk bitmap}  Rather than scanning all committed
pages linearly, the compressor maintains a bitmap with one bit per
64-page chunk.  A set bit indicates at least one non-EMPTY page.
The bitmap is rebuilt each tick.  Iteration uses
count-trailing-zeros to jump to set bits, reducing scan time from
$O(\text{committed})$ to $O(\text{active pages})$.

\paragraph{Per-worker state}  Each worker has its own LZ4 state
buffer, zstd compression context (\texttt{ZSTD\_CCtx}), page-sized
scratch buffer, and compression output buffer.  Workers share only the
dictionary lookup table (read-only during compression) and the
sharded compressed data~store.

\paragraph{Sharded CompressStore}  Compressed page data is stored
in a pool with 8~independent shards, each with its own spinlock
and free lists.  Pages are assigned to shards by index modulo~8.
With two workers and eight shards, lock contention is near~zero.

\begin{figure}[t]
\begin{algorithmic}[1]
\Function{CompressorTick}{}
  \State rebuild chunk bitmap
  \State partition page range across workers
  \State $\triangleright$ \textit{Phase 1: update cold counts}
  \ForAll{active pages $p$ (via chunk bitmap)}
    \If{$p$ was accessed since last tick}
      \State $\mathit{cold}[p] \gets 0$
    \Else
      \State $\mathit{cold}[p] \mathrel{+}= 1$
    \EndIf
  \EndFor
  \State $\triangleright$ \textit{Phase 2: compress cold pages}
  \ForAll{pages $p$ with $\mathit{cold}[p] \geq \textsc{ColdTicks}$}
    \State \Call{CompressPage}{$p$}
  \EndFor
  \State $\triangleright$ \textit{Phase 3: set up access monitoring}
  \ForAll{remaining \textsc{active} pages $p$}
    \State \Call{mprotect}{$p$, \textsc{prot\_read}}
    \State $\mathit{state}[p] \gets$ \textsc{active\_monitoring}
  \EndFor
\EndFunction
\Statex
\Function{CompressPage}{$p$}
  \State \Call{Lock}{$p$};\; $\mathit{state}[p] \gets$ \textsc{compressing}
  \State $\mathit{buf} \gets$ copy page into worker scratch buffer
  \State zero freed slots in $\mathit{buf}$ (non-temporal stores)
  \State \Call{mprotect}{$p$, \textsc{prot\_none}}
  \If{$\mathit{state}[p] \neq$ \textsc{compressing}}
    $\triangleright$ \textit{preempted by fault}
    \State \Call{Unlock}{$p$};\; \Return
  \EndIf
  \State $\mathit{algo} \gets$ \textbf{if} $\mathit{cold}[p] \geq$ \textsc{VeryCold} \textbf{then} zstd-9 \textbf{else} LZ4
  \State $\mathit{blob} \gets \Call{Compress}{\mathit{buf}, \mathit{algo}}$
  \If{$|\mathit{blob}| > 0.75 \times \textsc{PageSize}$}
    \State restore page;\; \Call{Unlock}{$p$};\; \Return
  \EndIf
  \State store $\mathit{blob}$ in sharded \textsc{CompressStore}
  \State \Call{Decommit}{$p$};\; $\mathit{state}[p] \gets$ \textsc{compressed}
  \State \Call{Unlock}{$p$}
\EndFunction
\end{algorithmic}

\subsection{Fault Handler}
\label{sec:impl:fault}

\sys installs a signal handler for both SIGSEGV and SIGBUS.  The
handler receives the faulting address, looks up the page index in the
VM region, acquires the per-page lock, and takes action based on page
state.  For a \textsc{compressed} page, the handler recommits the
physical page, decompresses the stored data, releases the compressed
blob, and transitions to \textsc{active}.  For a \textsc{compressing}
page, the handler recommits the page (the compressor has a copy in its
scratch buffer) and transitions to \textsc{active}; the compressor
detects the state change and abandons the compression.  For an
\textsc{active\_monitoring} page (a write to a read-only monitored
page), the handler restores read-write permission and transitions to
\textsc{active}.  Finally, a fault on an \textsc{active} page
indicates a race where Phase~3's batched \texttt{mprotect} overwrote a
per-page permission restoration from a concurrent fault handler; the
handler restores write~permission.

\begin{figure}[t]
\begin{algorithmic}[1]
\Function{HandleFault}{$\mathit{addr}$}
  \State $p \gets \Call{PageIndex}{\mathit{addr}}$
  \State \Call{Lock}{$p$}
  \If{$\mathit{state}[p] =$ \textsc{compressed}}
      \State $\mathit{slot} \gets \Call{AcquireFaultSlot}{}$
      $\triangleright$ \textit{CAS}
      \State \Call{Decompress}{$\mathit{slot.dctx}$, $\mathit{blob}$, $\mathit{slot.buf}$}
      \State \Call{Recommit}{$p$};\; copy $\mathit{slot.buf} \to p$
      \State release compressed blob;\; \Call{ReleaseFaultSlot}{$\mathit{slot}$}
      \State $\mathit{state}[p] \gets$ \textsc{active};\; $\mathit{cold}[p] \gets 0$
      \State \Call{PrefetchAdjacent}{$p$}
  \ElsIf{$\mathit{state}[p] =$ \textsc{compressing}}
      \State \Call{Recommit}{$p$}
      $\triangleright$ \textit{compressor detects \& aborts}
      \State $\mathit{state}[p] \gets$ \textsc{active}
  \ElsIf{$\mathit{state}[p] =$ \textsc{active\_monitoring}}
      \State \Call{mprotect}{$p$, \textsc{prot\_read|write}}
      \State $\mathit{state}[p] \gets$ \textsc{active}
  \EndIf
  \State \Call{Unlock}{$p$}
\EndFunction
\end{algorithmic}

\paragraph{Per-slot decompression contexts}
The signal handler must not call \texttt{malloc}.  All decompression
state is pre-allocated from a bootstrap allocator.  \sys maintains
32~fault slots, each with a pre-allocated page buffer and an
independent zstd decompression context.  A faulting thread atomically
acquires a slot via compare-and-swap, decompresses into the slot's
buffer, copies the result to the faulting page, and releases the slot.
This design supports up to 32~concurrent page faults without
data~races.

\paragraph{Prefetch}
After decompressing a faulted page, the handler speculatively
decompresses up to \texttt{kPrefetchWindow} = 2 pages in each
direction, provided they belong to the same span and are in the
COMPRESSED state.  Prefetch uses non-blocking \texttt{tryLock} to
avoid deadlock with concurrent fault handlers.  Prefetch reduces
cold-access latency in sequential access patterns; memcached's cold
key re-access throughput improves by 54\% with prefetch.

\paragraph{Bootstrap allocator}
All \sys internal metadata (page state arrays, compressed data store,
decompression contexts, worker buffers) is allocated from a bump
allocator (\texttt{BootstrapAlloc}) backed by \texttt{mmap}.  The
bootstrap allocator never calls \texttt{malloc} and never frees memory.
This design is critical for the signal handler path, which must
be async-signal-safe.

\paragraph{Thread initialization}
On macOS, the Objective-C runtime creates threads during dyld
initialization, so the compressor is started after the second
\texttt{threadInit} call to avoid interfering with early
bootstrapping.  On Linux, no such threads are created; instead,
\sys registers a GCC constructor function (priority~201) that calls
\texttt{threadInit} for the main thread and starts the compressor
immediately.  The priority ensures that the allocator itself
(priority~200) is initialized~first.

\subsection{Syscall Compatibility}
\label{sec:impl:syscall}

Kernel system calls access userspace buffers directly through
\texttt{copyin}/\texttt{copyout}.  If \sys has marked a buffer page
as \texttt{PROT\_READ} (monitoring) or \texttt{PROT\_NONE}
(compressed), the kernel returns EFAULT rather than triggering a
signal.  This affects any syscall that accesses userspace memory:
\texttt{read}, \texttt{write}, \texttt{recv}, \texttt{send},
\texttt{kevent}, and~others.

\sys interposes on $\sim{}20$ system calls and C library I/O functions.
Before each call, the wrapper walks the buffer's pages, touching any
page managed by \sys to trigger decompression via the fault handler,
then pins the pages to prevent the compressor from re-protecting them
during the syscall.  After the syscall returns, pages are unpinned.

Page pins are implemented as per-page atomic counters
(\texttt{g\_page\_pins}).  The compressor skips pages with a nonzero
pin count in both Phase~2 (compression) and Phase~3
(monitoring).

\paragraph{Buffered I/O (macOS)}  On macOS, DYLD interposition only
intercepts cross-dylib calls.  When the application calls
\texttt{fread}, the C library internally calls \texttt{read} within
the same dylib (libSystem); \sys's \texttt{read} interposition does
not see this internal call.  \sys addresses this by also interposing
\texttt{fread}, \texttt{fgets}, \texttt{fgetc}, \texttt{fwrite}, and
\texttt{fflush}, warming both the user buffer and the
\texttt{FILE} struct's internal buffer.  Additionally, the
compressor permanently pins the internal buffers of \texttt{stdin},
\texttt{stdout}, and \texttt{stderr} on its first tick, covering
the intra-libSystem blind spot for standard streams.

\paragraph{Linux syscall wrappers}
On Linux, \texttt{LD\_PRELOAD} overrides \emph{all} calls to an
interposed function, including calls within glibc itself.
Consequently, \texttt{fread}'s internal call to \texttt{read} is
intercepted, and separate buffered-I/O wrappers are unnecessary.
However, Linux introduces a different challenge: glibc invokes
\texttt{read}, \texttt{write}, and \texttt{poll} during early
process startup, before any constructors run.  On macOS, the
interpose mechanism is passive (the dynamic linker fills in the
original function pointer before any code executes), but on Linux
the wrappers must resolve the original function via \texttt{dlsym},
which is unavailable during early~init.

\sys solves this with \emph{lazy resolution}: each wrapper stores a
static function pointer initialized to \texttt{nullptr} and calls
\texttt{dlsym} on first invocation.  If the pointer is still null
(because \texttt{dlsym} is not yet available, or because
\texttt{dlsym} itself triggered the wrapper recursively), the wrapper
falls through to a raw \texttt{syscall()} path.  This is safe because
no pages are compressed during early initialization.  An atomic
recursion guard prevents infinite loops when \texttt{dlsym}'s internal
heap allocation triggers the wrapped \texttt{read} or
\texttt{write}~calls.

Linux event-driven servers (memcached, Redis) use \texttt{epoll}
rather than macOS's \texttt{kevent}.  \sys wraps both
\texttt{epoll\_wait} and \texttt{epoll\_pwait}, warming and
pinning the output event array.  These wrappers bypass
\texttt{dlsym} entirely and always invoke the kernel directly via
raw \texttt{syscall()}, avoiding self-resolution issues.
Similarly, the \texttt{poll} wrapper converts its millisecond
timeout to a \texttt{timespec} for the \texttt{ppoll} syscall,
since aarch64 Linux does not provide a \texttt{poll}
syscall~number.

All syscall wrappers require explicit default visibility
annotations, since the library is compiled with hidden visibility
by default; without this, the dynamic linker cannot see the
wrapper symbols for~interposition.
