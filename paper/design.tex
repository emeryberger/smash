\section{Design}
\label{sec:design}

\subsection{Design Overview}
\label{sec:design:arch}

\sys is designed around the principle that a memory allocator possesses
structural knowledge that can dramatically improve page
compressibility.  A slab page may contain a mix of live objects and
freed slots holding stale data from previous occupants; the allocator
knows which slots are free and can zero them before compression.
Objects allocated from the same call site tend to have similar
structure; the allocator can route these allocations to dedicated
pages.  The allocator also tracks which size class occupies each page,
enabling per-size-class compression policies that skip data patterns
that do not compress well.  \sys exploits all three forms of knowledge
to achieve high compression ratios with little impact on latency or
throughput: it defers zeroing of freed slots to compression time to
create compressible runs, routes allocations by call site to produce
homogeneous pages, and applies progressively stronger compression to
longer-idle pages.

\sys is a slab-based allocator that interposes on \texttt{malloc},
\texttt{free}, \texttt{realloc}, and related functions via the alloc8
interposition framework~\cite{berger2025alloc8}, which uses
\texttt{DYLD\_INSERT\_LIBRARIES} on macOS and \texttt{LD\_PRELOAD} on
Linux.  Applications link against the system allocator normally; \sys
replaces it at load time.

\paragraph{Scalability}  \sys avoids global locks on the
allocation fast path.  Each application thread has a private
thread cache that satisfies most \texttt{malloc} and \texttt{free}
calls without any synchronization.  When the cache must be refilled
or drained, it accesses per-arena, per-size-class slab free lists
protected by fine-grained spinlocks; four arenas spread contention
across 144 independent lists ($4 \times 36$ size classes).
When a thread cache drains, freed objects are returned to the
global slab free lists (bucketed by arena), where any thread can
reuse them; this approach avoids memory
blowup~\cite{berger2000hoard} despite per-thread caching.  The
background compressor partitions work across parallel workers, each
with private compression state, and stores compressed data in an
8-shard pool to avoid serialization.  Signal-handler
decompression uses 32 pre-allocated fault slots acquired via
compare-and-swap, supporting 32~concurrent page faults with no shared
mutable state.

Figure~\ref{fig:arch} shows the high-level architecture.  The
allocator manages heap pages through a virtual memory region (up to
16\,GiB).  Each page transitions through a state machine:

\begin{enumerate}
\item \textbf{EMPTY}: Page has never been allocated or has been
  returned to the OS.
\item \textbf{ACTIVE}: Page contains live objects with full
  read/write access.
\item \textbf{ACTIVE\_MONITORING}: Page has been marked read-only
  (\texttt{mprotect} with \texttt{PROT\_READ}) to detect future writes.
\item \textbf{COMPRESSING}: Compressor is actively compressing
  this page.
\item \textbf{COMPRESSED}: Page data is stored in compressed form;
  the physical page has been decommitted.
\end{enumerate}

A background compressor thread wakes every second and executes three phases:
(1)~update per-page cold counts based on access bits,
(2)~compress pages whose cold count exceeds a threshold, and
(3)~set up monitoring (\texttt{PROT\_READ}) on remaining active pages.

When the application accesses a compressed or monitored page, a
SIGSEGV or SIGBUS signal fires.  The fault handler decompresses the
page (or restores write permission for monitored pages) and returns,
allowing the faulting instruction to retry transparently.

\subsection{Call-Site Arena Segregation}
\label{sec:design:arenas}

\sys uses 36 size classes with sub-linear spacing: every 16
bytes from 16--128\,B, then four classes per power-of-two group
(e.g., 160/192/224/256) up to 16\,KiB.  This spacing follows standard
allocator practice~\cite{berger2001composing}.  \sys maintains
four arenas (configurable as a power of two).  Each arena has
independent slab free lists for all 36 size classes, organized as
a flat array indexed by arena and class.

On each \texttt{malloc} call, \sys selects an arena by hashing the
return address:

\begin{lstlisting}
uintptr_t h =
    __builtin_return_address(0) ^
    __builtin_return_address(1);
h ^= h >> 16;
arena = h & (kNumArenas - 1);
\end{lstlisting}

XORing two stack depths ensures different arena routing even when
allocations pass through a common wrapper function.  The hash maps
each unique (caller, grandcaller) pair to a deterministic arena.
Allocations from the same call site consistently land in the same
arena, producing pages with structurally homogeneous content.

On \texttt{free}, the thread cache drains objects back to their
originating arena by looking up each pointer's span in the page map
and reading the span's \texttt{arena\_id} field.  This routing prevents arena
mixing during deallocation.

\subsection{JIT Compression}
\label{sec:design:adaptive}

Just as a JIT compiler applies increasing levels of optimization to
hot code, \sys applies increasing levels of compression to cold
data.  A page progresses through two tiers as it remains unaccessed.
Pages idle for at least 2~seconds are compressed with LZ4 at
acceleration level~1; LZ4 compresses at $\sim$1\,GB/s and decompresses
at $\sim$4--6\,GB/s, making it suitable for pages that may be accessed
again soon.  Pages that remain cold for at least 1~minute are
recompressed with zstd at level~9, which achieves 2--15\% better
compression than LZ4 on structured data
(Table~\ref{tab:algo_compare}) at 10$\times$ lower throughput;
decompression speed is comparable across levels (1.2--1.8\,GB/s).  If
a compressed page is accessed, it is decompressed and its cold count
resets to zero---analogous to a JIT deoptimization.  The page will be
recompressed only if it goes cold again.

\paragraph{Per-size-class skip statistics}
Not all size classes compress well.  \sys maintains a 64-entry sliding
window of compression ratios for each size class.  The window records
the compression ratio (0--255, mapping to 0--100\%) of each attempted
compression.  If the average ratio across at least 32 samples falls
below 5\% space savings, \sys skips LZ4 compression attempts for that
size class.  The sliding window allows recovery: if the data pattern
changes and new pages compress well, the old poor-ratio samples age
out.

\subsection{Lazy Free and Zero-on-Free}
\label{sec:design:zero}

\sys's \texttt{free()} is lazy: it returns the pointer to a
per-thread cache and returns immediately ($\sim$21\,ns).  No
zeroing, no lock acquisition, and no interaction with the
compressor occur on the free path.  Freed slots are not reclaimed
by the slab until the thread cache drains a batch.

Partially-filled slab pages therefore contain a mix of live objects
and freed slots.  Freed slots hold stale data from their previous
occupants, which reduces compression ratios.  \sys zeros freed
slots \emph{lazily at compression time}, replacing stale data with
zero runs that LZ4 and zstd compress efficiently.

Before compressing a page, the compressor copies the page into a
scratch buffer, iterates the span's free bitmap to identify freed
slots, and zeros them using non-temporal stores
(\texttt{stnp}/\texttt{movnti}) to avoid cache pollution.  Deferring all zeroing to
compression time keeps the free path fast regardless of object
size.

\subsection{Parallel Compressor}
\label{sec:design:parallel}

The compressor uses a coordinator-worker model with
two parallel workers (configurable).  The coordinator thread wakes
every second, partitions the committed page range across workers,
and dispatches each of the three phases.

\paragraph{Chunk bitmap}  Rather than scanning all committed
pages linearly, the compressor maintains a bitmap with one bit per
64-page chunk.  A set bit indicates at least one non-EMPTY page.
The bitmap is rebuilt each tick.  Iteration uses
count-trailing-zeros to jump to set bits, reducing scan time from
$O(\text{committed})$ to $O(\text{active pages})$.

\paragraph{Per-worker state}  Each worker has its own LZ4 state
buffer, zstd compression context (\texttt{ZSTD\_CCtx}), page-sized
scratch buffer, and compression output buffer.  Workers share only the
dictionary lookup table (read-only during compression) and the
sharded compressed data store.

\paragraph{Sharded CompressStore}  Compressed page data is stored
in a pool with 8~independent shards, each with its own spinlock
and free lists.  Pages are assigned to shards by index modulo~8.
With 2~workers and 8~shards,
lock contention is near zero.

\begin{figure}[t]
\begin{algorithmic}[1]
\Function{CompressorTick}{}
  \State rebuild chunk bitmap
  \State partition page range across workers
  \ForAll{active pages $p$ (via chunk bitmap)}
    \Comment{Phase 1}
    \If{$p$ was accessed since last tick}
      \State $\mathit{cold}[p] \gets 0$
    \Else
      \State $\mathit{cold}[p] \mathrel{+}= 1$
    \EndIf
  \EndFor
  \ForAll{pages $p$ with $\mathit{cold}[p] \geq \textsc{ColdTicks}$}
    \Comment{Phase 2}
    \State \Call{CompressPage}{$p$}
  \EndFor
  \ForAll{remaining \textsc{active} pages $p$}
    \Comment{Phase 3}
    \State \Call{mprotect}{$p$, \textsc{prot\_read}}
    \State $\mathit{state}[p] \gets$ \textsc{active\_monitoring}
  \EndFor
\EndFunction
\Statex
\Function{CompressPage}{$p$}
  \State \Call{Lock}{$p$};\; $\mathit{state}[p] \gets$ \textsc{compressing}
  \State $\mathit{buf} \gets$ copy page into worker scratch buffer
  \State zero freed slots in $\mathit{buf}$ (non-temporal stores)
  \State \Call{mprotect}{$p$, \textsc{prot\_none}}
  \If{$\mathit{state}[p] \neq$ \textsc{compressing}}
    \Comment{preempted by fault}
    \State \Call{Unlock}{$p$};\; \Return
  \EndIf
  \State $\mathit{algo} \gets$ \textbf{if} $\mathit{cold}[p] \geq$ \textsc{VeryCold} \textbf{then} zstd-9 \textbf{else} LZ4
  \State $\mathit{blob} \gets \Call{Compress}{\mathit{buf}, \mathit{algo}}$
  \If{$|\mathit{blob}| > 0.75 \times \textsc{PageSize}$}
    \State restore page;\; \Call{Unlock}{$p$};\; \Return
  \EndIf
  \State store $\mathit{blob}$ in sharded \textsc{CompressStore}
  \State \Call{Decommit}{$p$};\; $\mathit{state}[p] \gets$ \textsc{compressed}
  \State \Call{Unlock}{$p$}
\EndFunction
\end{algorithmic}
\caption{\textbf{Background compressor tick}
  (\S\ref{sec:design:parallel}).  Three phases run in parallel
  across disjoint page ranges.  \textsc{CompressPage} zeros freed
  slots lazily, selects LZ4 or zstd based on cold duration (JIT
  compression), and decommits the physical page on success.}
\label{fig:algo:compress}
\end{figure}

\subsection{Fault Handler}
\label{sec:design:fault}

\sys installs a signal handler for both SIGSEGV and SIGBUS.  The
handler receives the faulting address, looks up the page index in the
VM region, acquires the per-page lock, and takes action based on page
state.  For a \textsc{compressed} page, the handler recommits the
physical page, decompresses the stored data, releases the compressed
blob, and transitions to \textsc{active}.  For a \textsc{compressing}
page, the handler recommits the page (the compressor has a copy in its
scratch buffer) and transitions to \textsc{active}; the compressor
detects the state change and abandons the compression.  For an
\textsc{active\_monitoring} page (a write to a read-only monitored
page), the handler restores read-write permission and transitions to
\textsc{active}.  Finally, a fault on an \textsc{active} page
indicates a race where Phase~3's batched \texttt{mprotect} overwrote a
per-page permission restoration from a concurrent fault handler; the
handler simply restores write permission.

\begin{figure}[t]
\begin{algorithmic}[1]
\Function{HandleFault}{$\mathit{addr}$}
  \State $p \gets \Call{PageIndex}{\mathit{addr}}$
  \State \Call{Lock}{$p$}
  \If{$\mathit{state}[p] =$ \textsc{compressed}}
      \State $\mathit{slot} \gets \Call{AcquireFaultSlot}{}$
      \Comment{CAS}
      \State \Call{Decompress}{$\mathit{slot.dctx}$, $\mathit{blob}$, $\mathit{slot.buf}$}
      \State \Call{Recommit}{$p$};\; copy $\mathit{slot.buf} \to p$
      \State release compressed blob;\; \Call{ReleaseFaultSlot}{$\mathit{slot}$}
      \State $\mathit{state}[p] \gets$ \textsc{active};\; $\mathit{cold}[p] \gets 0$
      \State \Call{PrefetchAdjacent}{$p$}
  \ElsIf{$\mathit{state}[p] =$ \textsc{compressing}}
      \State \Call{Recommit}{$p$}
      \Comment{compressor detects \& aborts}
      \State $\mathit{state}[p] \gets$ \textsc{active}
  \ElsIf{$\mathit{state}[p] =$ \textsc{active\_monitoring}}
      \State \Call{mprotect}{$p$, \textsc{prot\_read|write}}
      \State $\mathit{state}[p] \gets$ \textsc{active}
  \EndIf
  \State \Call{Unlock}{$p$}
\EndFunction
\end{algorithmic}

  (\S\ref{sec:design:fault}).  Each of 32~pre-allocated fault slots
  has an independent decompression context, supporting concurrent
  faults with no heap allocation.}
\label{fig:algo:fault}
\end{figure}

\paragraph{Per-slot decompression contexts}
The signal handler must not call \texttt{malloc}.  All decompression
state is pre-allocated from a bootstrap allocator.  \sys maintains
32~fault slots, each with a pre-allocated page buffer and an
independent zstd decompression context.  A faulting thread atomically
acquires a slot via compare-and-swap, decompresses into the slot's
buffer, copies the result to the faulting page, and releases the slot.
This design supports up to 32~concurrent page faults without data races.

\paragraph{Prefetch}
After decompressing a faulted page, the handler speculatively
decompresses up to \texttt{kPrefetchWindow} = 2 pages in each
direction, provided they belong to the same span and are in the
COMPRESSED state.  Prefetch uses non-blocking \texttt{tryLock} to
avoid deadlock with concurrent fault handlers.  Prefetch reduces
cold-access latency in sequential access patterns; memcached's cold
key re-access throughput improves by 54\% with prefetch enabled.

\paragraph{Bootstrap allocator}
All \sys internal metadata (page state arrays, compressed data store,
decompression contexts, worker buffers) is allocated from a bump
allocator (\texttt{BootstrapAlloc}) backed by \texttt{mmap}.  The
bootstrap allocator never calls \texttt{malloc} and never frees memory.
This design is critical for the signal handler path, which must be
async-signal-safe.

\subsection{Syscall Compatibility}
\label{sec:design:syscall}

Kernel system calls access userspace buffers directly through
\texttt{copyin}/\texttt{copyout}.  If \sys has marked a buffer page
as \texttt{PROT\_READ} (monitoring) or \texttt{PROT\_NONE}
(compressed), the kernel returns EFAULT rather than triggering a
signal.  This behavior affects any syscall that reads from or writes to
userspace memory: \texttt{read}, \texttt{write}, \texttt{recv},
\texttt{send}, \texttt{kevent}, and others.

\sys interposes on 20 system calls and C library I/O functions.
Before each call, the wrapper walks the buffer's pages, touching any
page managed by \sys to trigger decompression via the fault handler,
then pins the pages to prevent the compressor from re-protecting them
during the syscall.  After the syscall returns, pages are unpinned.

Page pins are implemented as per-page atomic counters
(\texttt{g\_page\_pins}).  The compressor skips pages with a nonzero
pin count in both Phase~2 (compression) and Phase~3 (monitoring).

\paragraph{Buffered I/O}  On macOS, DYLD interposition only
intercepts cross-dylib calls.  When the application calls
\texttt{fread}, the C library internally calls \texttt{read} within
the same dylib (libSystem); \sys's \texttt{read} interposition does
not see this internal call.  \sys addresses this by also interposing
\texttt{fread}, \texttt{fgets}, \texttt{fgetc}, \texttt{fwrite}, and
\texttt{fflush}, warming both the user buffer and the \texttt{FILE}
struct's internal buffer (\texttt{stream->\_bf.\_base}).
Additionally, the compressor permanently pins the internal buffers of
\texttt{stdin}, \texttt{stdout}, and \texttt{stderr} on its first
tick, covering the intra-libSystem blind spot for standard streams.
